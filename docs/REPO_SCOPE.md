# 本仓的射程 —— 什么该进这个仓，以及它**不**主张什么

> **姊妹文档：** [`DISCLOSURE_POLICY.md`](DISCLOSURE_POLICY.md) 答的是「**什么不能进**」（并有一道机械门）。
> 本文答的是「**什么该进**」，以及为什么有些东西**即使可以公开也不该公开**。
> 两者原本是同一个问题的两半，而此前只写了一半 —— 于是每一件新产物都要重新争论一次落点，
> 而每次争出的判据都不进任何文档。**本文补上另一半。**

---

## 1. 初衷

**方法论公开 · 可验证 · 可信。**

`README` 里的三件，是这条初衷的全部载体：

```
① 一份公开语料      让人能真的跑起来（含配对的良性对照集 —— 只测拦截率的检测器可以拿满分）
② 一个评测引擎      驱动被治理的目标、读它自己的审计日志作为证据、按成熟度登记表评级
③ 一个独立校验器    ~200 行、只用标准库 —— 指着一份审计日志自己验哈希链，
                    【不必信任写这份日志的人】
```

🔴 **承诺是「你能自己跑一遍」，不是「你能复算我们发布的数字」。**
这两件事长期被当成一件。本文把它们分开，见 §4。

---

## 2. 🔴 克制 —— 本仓**不**主张的东西

这一节比上一节重要。一个方法论最容易被读成比它声称的更强的东西，而**读者读到什么，
决定它可不可信**。

```
❌ 不是一套顶级评测方法       它是【一家之言】：一种把治理主张从"声称"推向"实测"的做法，
                              供人检视、批评、取用。近几个月也没有出现顶级的架构与设计，
                              这一点我们照实写在这里，而不是等别人指出来。
❌ 不是一份基准（benchmark）   仓里的语料是**够用的样本**，不是有代表性的总体。
                              没有任何抽样论证支撑"覆盖了什么"。
❌ 不是行业标准或合规认定       与任何框架的对照见 `FRAMEWORK_ALIGNMENT.md`，那是【对照】不是【认定】。
❌ 不承诺第三方能复算我方数字   见 §4。
```

**⇒ 由此得到一条对读者的请求：** 若你要引用本仓的方法，请引用**方法**；
若你要引用一个**数**，请自己跑一遍拿你自己的数 —— 这正是 `README` 最后那句
「Run it against *your* deployment, with *your* corpus, and get *your own* report」的意思。

## 3. 成员规则

> 🔴 **一件产物进公开仓，当且仅当【第三方为了跑自己的评测】需要它。
> 为了产出【我方自己的数字】而存在的产物，不进。**

**用既有决定回测（四件，无一需要特例）：**

| 产物 | 它为谁存在 | 落点 |
|---|---|---|
| 评测引擎 · 独立校验器 | 承诺的主体 | **公开** |
| 通用注入语料 + 配对良性对照集 | 别人要跑起来就需要一份语料 | **公开** |
| 一次性留出臂（认证用） | 只为产出我方的认证数字；且读一次即作废 | **仓外** |
| 领域语料（如中文金融集） | 我方的数字 + 领域资产 | **仓外** |

## 3.1 🔴 领域语料为什么即使可公开也不公开

这条单列，因为它最反直觉：**公开更多语料看起来总是更透明。**

```
公开一份领域语料，读者会读到的不是「这是我们用过的一批样本」，
而是「这是这个领域该怎么测」—— 一个【覆盖面】主张。
🔴 而我们支撑不了那个主张：没有抽样论证、没有代表性论证，样本量也不足以支撑。
⇒ 于是公开它，把一个诚实的【方法论】主张，换成了一个撑不住的【覆盖面】主张。
```

**对可信度是净损失，不是净收益。** 这正是本仓在别处反复记录的那一族缺陷：
**一个东西被读成比它声称的更强的东西** —— 而这一次，读错的成本由方法论的可信度承担。

⚠️ **一条必须一起说的代价**：仓外语料产出的数字，第三方无法自行复核。
我们**主动声明**这一点，而不是让它藏在"引擎是开源的"这句话后面。见 §4。

## 4. 「可复算」的作用域

```
✅ 可复算的     引擎的行为 · 审计链的完整性 · 你自己那一跑的全部结果
                （拿你的语料、你的部署、你的日志 —— 不需要信任我们）
🔴 不可复算的   我方用【仓外语料】产出的数字
                我们不提供那些语料 ⇒ 那些数不是"任何人都能复算"的
```

**⇒ 凡引用我方数字的材料，必须带这个作用域限定。**
一个不带作用域的"可复算"，比不说更坏 —— 它让读者以为自己核过了。

## 5. 仓外产物在本仓留什么

一件产物落仓外，**不等于它在本仓无痕**：

```
登记条目    臂的名字 · 内容哈希 · 它为哪一个指标服务 —— 零用例文本
引用式契约  harness 以 `--corpus-dir` 指向仓外根；`corpus_sha` 机制不变
```
🔴 **让「这里有一条我们看不到的臂」成为一个**可读的事实**，而不是一处沉默。
一次缺席若连一个空格子都不留，就没有任何东西会红。

## 6. 本文怎么用

新增一件产物时，按顺序问三句：

```
① 第三方为了跑【他自己的】评测，需要它吗？      不需要 ⇒ 仓外，到此为止
② 它公开之后会被读成一个【覆盖面】主张吗？      会   ⇒ 仓外（§3.1）
③ `DISCLOSURE_POLICY.md` 那道门放行吗？         不放 ⇒ 仓外
```

⚠️ **公开是不可逆的。** 一次公开撤不回历史、撤不回任何 clone 与 fork。
⇒ **在不可逆的选择上，默认站在可逆的那一边**：先仓外，将来想公开随时可以。
