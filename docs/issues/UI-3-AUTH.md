# UI-3-AUTH — 案级服务的访问控制：把共享密钥做成一个像样的模块

> **Problem（普通话）：** [UI-3](UI-3.md) 的案级服务守的是**绕过地图** ——
> 一份"哪条手法能打穿这个网关"的清单。它今天的访问控制是：
> 一个 JSON 文件里 `{裸 token 串: 租户}`，页面上让人**粘一串没有身份的密钥**，
> **不过期、不能撤、看过不留痕**。
>
> 🔴 **这不是"因为不长身份系统所以只能这样"** —— 那是架构约束，不是简陋的许可。
> **两回事：**「不引入用户表/口令/OIDC」是**约束**；
> 「密钥没有名字、没有有效期、谁看过没人知道」是**没做完**。
>
> **Value:** 在**完全不越过那条约束**的前提下，把它做成一个能交付的访问控制模块：
> **密钥有身份、有有效期、可撤销、可轮换，且每一次访问都留痕。**
> 🔴 **最后那条是"专业 vs demo"的真正分界** —— 一份 operator_only 的绕过地图，
> **谁看过必须有记录**；登录框好不好看是次要的。
>
> Design brief. **归属：** Implementer 编码 + 测试。**规模：中。**
> **前置：** UI-3 已合（`cases_auth.py` / 访问页 / cookie 会话已在）。**无外部依赖。**

---

## 0. 起点核对（2026-08-07，按 UI-3a 已合并的实况重刷）

**本单不是从零开始** —— UI-3a 已经把"人怎么进来"这一层建好了。**先钉住哪些已在、哪些没有**，
免得实现者重造已有的东西、或以为已有的东西已经够。

| | 状态 | 落点 |
|---|---|---|
| 访问页（不是浏览器弹框） | ✅ **已在** | `cases_app.py` `_access_page` |
| `POST /session` + HttpOnly·SameSite=Strict cookie | ✅ **已在** | `_COOKIE`（🔴 **cookie 里就是那把共享密钥本身，没有服务端会话** —— 与 §1.1 一致） |
| 退出 | ✅ **已在** | `GET /logout` · 模板 `show_logout` |
| Basic（`curl -u :key`）/ header / Bearer | ✅ **已在** | 脚本与 CI 通道 |
| 深链回跳 `?next=` + 开放重定向净化 | ✅ **已在** | `_safe_next` |
| 凭据 → 租户作用域（403 越权 / 404 不确认存在） | ✅ **已在** | `cases_auth.py` |
| **密钥有名字 / 有效期 / 可撤销** | ❌ **没有** —— 映射仍是 `{裸串: 租户}` | 件 A · 件 B |
| **热生效** | ❌ **没有** —— `create_cases_app` **只在启动时读一次**映射 | 件 B |
| 🔴 **访问留痕** | ❌ **一条都没有** | **件 C（本单主体）** |
| 失败恒定延迟 / 不可枚举 | ❌ 没有 | 件 D |

🔴 **两条因此发生的变化（相对本单初稿）：**

1. **件 A 的 UI 工作量下调** —— 是"往一个已有的页面上加身份显示"，不是"建一个登录面"；
2. 🔴 **有效期能自动生效，不用额外机制** —— 作用域是**每请求**用 `scope_for_token(token_map, supplied)`
   现查的（`_supplied` 只取出密钥、不缓存判定），所以把 `expires_at` 加进这一步，
   **已签发的 cookie 会在到期的下一次请求上失效**。
   **不要为此引入会话存储** —— 那正是 §1.1 禁掉的东西。

## 1. 🔴 范围先划死（这一节是硬边界，不许在实现时松动）

### 1.1 **不做**（越过即打回，不接受"顺手"）

| 不做 | 为什么 |
|---|---|
| **用户表 / 注册 / 用户名** | 一旦有"用户"，就得有找回、改密、去重、合并 —— Core 扛不动也不该扛（[EV-W1 D4](EV-W1.md)） |
| **口令 + 哈希 + 加盐** | 密钥是**机器发的高熵串**，不是人记的口令。引入口令就引入了口令的全部债务 |
| **OIDC / SAML / SSO 对接** | 客户**不一定有** SSO（PM 2026-08-04 已更正过一次这个假设）。Core 必须在裸部署下成立 |
| **角色 / 权限矩阵 / 继承** | 作用域只有两档：**一个租户** 或 `*`。第三档出现之前不许建模型 |
| **会话服务端存储（session store）** | cookie 里就是那个共享密钥本身；服务端不存会话，就没有会话过期清理、并发登录、单点登出这一串问题 |
| **多因素 / 验证码 / 限流之外的任何"安全增强"** | 不在本单，也不假装在 |

🔴 **一句话**：本单**不引入任何新的身份概念**。
它引入的全部东西是：**给已有的那把密钥加上元数据、生命周期和留痕。**

### 1.2 **做**（四件）

| # | 件 | 一句话 |
|---|---|---|
| **A** | **密钥有身份** | 每把密钥带 `label` / `scope` / `expires_at` / `note`；页面显示**"以 `<label>` 身份查看"**，不是让人对着一串 token 猜自己是谁 |
| **B** | **生命周期** | 到期即失效 · 可撤销 · **改映射文件热生效**（不重启） |
| **C** | 🔴 **访问留痕** | 每次**成功**访问追加一行：`label · 时间 · 动作 · 看的是哪一次跑`。**这是本单存在的主要理由** |
| **D** | **失败可见但不可枚举** | 失败也记（不记密钥内容）；对外仍是**同一句**错误文案 + 恒定延迟，**不许泄露"这把密钥存在但过期了"** |

## 2. 件 A — 密钥有身份

### 2.1 映射文件从"串→串"升级为"串→对象"

**今天**（UI-3）：

```json
{ "tok-a": "__eval__", "tok-admin": "*" }
```

**本单**：

```json
{
  "<key>": {
    "label":      "auditor-acme",           // 页面显示的身份，唯一，非空
    "scope":      "acme",                   // 租户 id，或 "*"（admin）
    "expires_at": "2026-12-31T00:00:00Z",   // 🔴 必填；不许 null 表示永久（见 §3.1）
    "note":       "Q4 外部审计，合同 #1234"   // 可选，运维备忘
  }
}
```

🔴 **旧格式（串→串）继续受理**，读入时归一为 `label=<租户名>` / `expires_at` 缺失。
**但启动时打一行 WARN 指名哪些行是旧格式** —— *不* fail-closed：
一条会让既有部署起不来的升级，一个月内会被人用"改回旧版本"绕过
（同 [DISCLOSURE_POLICY §1.1](../DISCLOSURE_POLICY.md) 的严重度校准）。

**校验（fail-closed，任一不满足即拒绝启动并指名那一行）**：
`label` 非空且**全局唯一** · `scope` 非空 · `expires_at` 可解析为 UTC 时刻 ·
`*` 仍必须是**显式**的 `scope` 值（[UI-3 §3.3](UI-3.md)）。

### 2.2 页面显示当前身份

顶部（分级带**之下**，不与它争位置）：

> **以 `auditor-acme` 身份查看 · 租户 `acme` · 有效至 2026-12-31 · 退出**

🔴 **admin 要显式标出**：`以 platform-admin 身份查看 · **全部租户（admin）**`。
**一个能看所有租户绕过地图的会话，必须在页面上一直说出来。**

**`label` 永远不许显示密钥本身**（回归：断言页面 HTML 里搜不到任何密钥串）。

**落点已存在**（§0）：`cases_base.html` 顶部已有分级带与 `show_logout`，
本件是**往那一行加身份**，不是新建一个面。
🔴 **位置在分级带之下** —— 分级带说"这是什么级别的数据"，身份说"你是谁"，
**两句不许互相挤掉**（分级带永远在最上，它是跟着截图走的那一句）。

## 3. 件 B — 生命周期

### 3.1 🔴 `expires_at` 必填，不设"永久"

**没有永久密钥这一档。** 想长期用就填一个远期日期 —— 那也是**一个日期**，
会出现在页面上、会被人看见、到期会提醒。
**"永久"是一种没人再看它一眼的状态**，而这把密钥开的是绕过地图。

- 过期 ⇒ 与"未知密钥"**同样处理**（§4.1），**不提示"已过期"**；
- 页面在**剩余 ≤14 天**时显示到期提醒（给运维时间轮换，不是到期当天才发现）。

### 3.2 撤销 = 从文件里删那一行

**没有撤销 API**（那会是一个写路径）。运维删行 ⇒ 下一次请求即失效。

### 3.3 热生效

**今天没有** —— `create_cases_app` 在**启动时读一次**映射，之后改文件不生效（§0）。

映射文件按 **mtime + size** 判变更，变了就重读（每次请求最多 `stat` 一次，不加缓存层）。

🔴 **不要顺手引入会话存储来"记住"已登录的人** —— 作用域本来就是每请求现查的（§0-2），
热重读之后**下一次请求自动按新映射判**，撤销与到期都因此自动成立。**这是既有设计给的便宜，别丢掉。**

- 重读**失败**（文件损坏/JSON 错）⇒ 🔴 **保留上一份可用映射并打 ERROR**，
  **不是**清空成"谁都进不来"，也**不是**回落成"谁都能进"。
  **一次编辑失误不该把正在审计的人踢出去，更不该把门打开。**

## 4. 件 C — 🔴 访问留痕（本单的主体）

### 4.1 记什么

**每一次**通过鉴权的请求，追加一行 JSONL：

```json
{"at":"2026-08-05T09:12:33Z","label":"auditor-acme","scope":"acme",
 "action":"view_run","run_key":"9de2dfde…","tenant":"acme","ok":true}
```

失败也记，但 🔴 **只记"有一次失败尝试"**：`{"at":…,"ok":false,"reason":"rejected"}` ——
**不记提交的密钥、不记它像哪一把、不记失败原因的细分**。
（记下失败密钥 = 把一份密钥字典写进日志。）

### 4.2 记在哪

`$TREVAL_CASES_ACCESS_LOG`，**默认写在案级库目录下** `access.jsonl`。
🔴 **它属于案级库那一侧的隔离域**（[UI-3 §5.3](UI-3.md)）——
**绝不写进报告库**，也**绝不进任何对外产物**。

### 4.3 🔴 它不是审计链，别让它冒充

| 它是 | 它不是 |
|---|---|
| 运维可读的**访问记录** | ❌ **不是**哈希链，**没有**防篡改保证（那是 WAL 的事） |
| 回答"谁看过这份绕过地图" | ❌ **不能**用来回答"没人看过"（能写的人也能删） |

**这两句要逐字印在文件头部**（首行一条 `{"_note": …}`），
理由与 `cases verify` 的作用域声明相同：**工件必须自带它的效力边界**，
否则一份"访问记录"迟早被当成"审计证据"引用。

### 4.4 页面上要能看

`GET /access-log` —— **admin（`scope="*"`）可见全部；租户作用域只见自己租户的行。**
🔴 **一个租户看得到"谁看过我的绕过地图"，这本身就是价值**，不只是运维排障。

### 4.5 写失败怎么办

🔴 **写不进去 ⇒ 拒绝服务该请求（fail-closed）。**
"看得到但没留痕"正是本单要消灭的状态 —— **不许降级成"记不上就算了"**。

---

## 5. 件 D — 失败可见但不可枚举

- 未知 / 过期 / 撤销 / 格式错 ⇒ **同一句**文案：`访问密钥无效`；
- 🔴 **响应时间恒定**（比较用常数时间；不因"这把存在但过期"而更快返回）；
- 同一来源的连续失败 ⇒ **递增延迟**（不是封禁 —— 封禁需要状态，超范围）；
- 失败**永不**出现在 URL、日志或页面上的任何密钥片段。

---

## 6. 非目标

- **不改** `scope_for_token` / `can_see_tenant` / `resolve_query_tenant` 的**语义**
  （403 越权、404 不确认存在 —— [UI-3 §3.3](UI-3.md) 一个字不动）；
- **不改**案级库、ingest 门、复算面、分级带；
- **不做**报告服务的鉴权（它是另一套姿态，本单不碰）；
- **不做** §1.1 列的任何一项。

## 8. 验收（每条先说什么输入让它红）

| # | 断言 | 🔴 让它红的输入 |
|---|---|---|
| 1 | 身份可见 | 登录后页面含 `以 <label> 身份查看`；🔴 **页面 HTML 里搜不到任何密钥串** |
| 2 | admin 显式 | `scope="*"` 的会话页面上必须出现 `全部租户（admin）`；删掉即红 |
| 3 | 过期 | 把 `expires_at` 调到过去 ⇒ **拒**，且文案与"未知密钥"**逐字相同** |
| 4 | 撤销 | 删掉那一行 ⇒ **下一次请求**即失效（无需重启） |
| 5 | 热生效 | 改 `scope` ⇒ 下一次请求按新 scope 判 |
| 6 | 🔴 坏文件不改变现状 | 把映射文件写成非法 JSON ⇒ **既有会话仍可用**、新登录按**上一份**判、日志有 ERROR —— **既不清空也不放行** |
| 7 | 🔴 留痕 | 一次成功访问 ⇒ `access.jsonl` **多一行**且含 `label`/`run_key`；**删掉写入调用，测试必须红** |
| 8 | 🔴 留痕不含密钥 | 用一把哨兵密钥登录并失败若干次 ⇒ 日志里**该串出现 0 次** |
| 9 | 🔴 写失败即拒 | 把日志目录改成只读 ⇒ 请求**被拒**（不是"看得到但没记上"） |
| 10 | 效力边界自述 | 日志首行含"非哈希链、不能证明无人访问"两句 |
| 11 | 租户只见自己 | 租户 A 的 `GET /access-log` 里 **grep 不到** B 的任何行；admin 能见两者 |
| 12 | 不可枚举 | 未知 / 过期 / 撤销三种输入的**响应文案与状态码逐字相同** |
| 13 | 隔离未破 | `access.jsonl` 在案级库侧；**报告库导出路径拿不到它** |
| 14 | 旧格式兼容 | 串→串的旧映射文件**仍能启动**，且**打 WARN 指名行** |

## 10. Live Test

```bash
export PYTHONPATH=$PWD
cat > ~/cases-tokens.json <<'EOF'
{ "<key-a>":     {"label":"auditor-acme",  "scope":"__eval__", "expires_at":"2026-12-31T00:00:00Z"},
  "<key-admin>": {"label":"platform-admin","scope":"*",        "expires_at":"2026-12-31T00:00:00Z"} }
EOF
TREVAL_CASES_TOKENS=~/cases-tokens.json TREVAL_CASE_STORE=~/casestore python -m treval.web.cases
```

**准备 —— 生成密钥、写映射、起服务**（初版只给了三个变量名、没给密钥怎么配，Live 时卡在这里）：

```bash
export PYTHONPATH=$PWD
S=~/casestore ; TOK=~/cases-tokens.json ; B=http://127.0.0.1:8091
KEY_A=$(python -c "import secrets;print(secrets.token_hex(32))")
KEY_ADMIN=$(python -c "import secrets;print(secrets.token_hex(32))")

cat > $TOK <<EOF          # 🔴 用 <<EOF 不是 <<'EOF' —— 要让 $KEY_* 展开
{ "$KEY_A":     {"label":"auditor-acme",  "scope":"__eval__","expires_at":"2026-12-31T00:00:00Z"},
  "$KEY_ADMIN": {"label":"platform-admin","scope":"*",       "expires_at":"2026-12-31T00:00:00Z"} }
EOF
chmod 600 $TOK            # 它就是密钥本体

# 先自检再起服务（映射有问题时，这里比 HTTP 更早、更清楚地报出来）
python -c "
from treval.web.cases_auth import load_token_map
for v in load_token_map('$TOK').values():
    print(f'{v.label:16s} scope={v.scope:10s} 到期={v.expires_at} legacy={v.legacy}')"

TREVAL_CASES_TOKENS=$TOK TREVAL_CASE_STORE=$S python -m treval.web.cases &
sleep 2
```

| 必填/易错 | 说明 |
|---|---|
| `label` · `scope` · `expires_at` | **三个都必填**；`expires_at` **不许 `null`**（§3.1：没有永久密钥） |
| `scope` | 必须等于案级契约里的 `tenant_id`；`"*"` = admin，**必须显式一行** |
| `label` | **全局唯一**，重名即拒绝启动 |
| 🔴 报错措辞 | 只报 **label 或行号**，**永不报 token** —— 报文里出现密钥 = 把密钥写进日志 |

🔴 **收尾必做**：`shred -u $TOK 2>/dev/null || rm -f $TOK` ——
Live 用过的密钥已进入**终端历史**，**不得用于任何真环境**。

### 10.1 件 A —— 密钥有身份（验收 1、2）

浏览器开 `$B/`，密钥填 `KEY_A`。

1. 顶部出现 **`以 auditor-acme 身份查看 · 租户 __eval__ · 有效至 2026-12-31 · 退出`**；
   🔴 **它在分级带之下** —— 分级带说"这是什么级别的数据"，身份说"你是谁"，两句都在。
   命令行核（**模板里 label 外包着 `<strong>`，模式必须允许标签**）：
   ```bash
   curl -s -u ":$KEY_A" $B/ | grep -o "以 <strong>[^<]*</strong> 身份查看[^<]*"
   ```
   > ⚠️ 初版写的是 `grep -o "以 [^<·]*身份查看"` —— 它**排除了 `<`，永远匹配不上**，
   > 于是"页面没渲染身份"和"我的正则写错了"分不开。**Live 时误报过一次。**
2. 🔴 **页面里搜不到密钥本身**：
   ```bash
   curl -s -u ":$KEY_A" $B/ | grep -c "$KEY_A"        # 期望 0
   ```
3. admin（`KEY_ADMIN`）登录 ⇒ 顶部**显式**出现 **`全部租户（admin）`**
   （🔴 一个能看所有租户绕过地图的会话，必须一直说出来）。

### 10.2 件 B —— 生命周期（验收 3–6、14）

4. **过期**：把 `KEY_A` 的 `expires_at` 改成过去的日期 ⇒ 再访问被拒，
   🔴 **文案与乱敲一个密钥逐字相同**：
   ```bash
   curl -s -u ":$KEY_A" $B/ | md5sum ; curl -s -u ":nonsense" $B/ | md5sum   # 🔴 两个 md5 必须一致
   ```
   🔴 **验完立刻把 `expires_at` 改回未来** —— 否则后面每一条用 `KEY_A` 的检查都会
   **因为"钥匙已死"而返回期望值**，而不是因为被测的那件事。
   **Live 时就这么空洞通过过两条**（见 10.3-11、10.4-14 的注）。
5. **撤销**：把那一行从映射里删掉 ⇒ **下一次请求**即失效，**不用重启**；
6. **热生效**：把 `scope` 从 `__eval__` 改成别的 ⇒ 下一次请求按新 scope 判；
7. 🔴 **坏文件不改变现状**：把 `$TOK` 写成非法 JSON ⇒
   **已登录的会话照常用**、新登录按**上一份**映射判、日志有 ERROR
   —— **既不清空（谁都进不来）也不放行（谁都能进）**；
8. **遗留格式宽限**：把 `$TOK` 换回旧的 `{"tok-a": "__eval__"}` 串→串格式 ⇒
   **仍能启动**，且**打 WARN 指名那一行**（🔴 fail-closed 的升级会被"退回旧版本"绕过）。

### 10.3 件 C —— 🔴 访问留痕（本单主体，验收 7–10、13）

9. 一次成功访问 ⇒ `access.jsonl` **多一行**且含 `label` / `action` / `tenant`：
   ```bash
   grep '"ok": true' $S/access.jsonl | tail -1 | python -m json.tool
   ```
   > 🔴 **必须 grep `ok: true`，不能直接 `tail -1`** —— 最后一行很可能是刚才那次**失败**，
   > 而失败**按设计只记 `{at, ok:false, reason}`**（不记密钥、不记细分原因）。
   > **Live 时看错行，误以为留痕没带 `label`。**
   > `run_key` 在列表页是 `null`（`action:"list"`），看某一次跑时才有值 —— **正常**。
10. 🔴 **留痕里没有密钥**：用一把哨兵密钥登录并**失败**若干次 ⇒
    ```bash
    grep -c "$SENTINEL_KEY" $S/access.jsonl        # 期望 0
    ```
    （失败只记"有一次失败尝试"——记下失败密钥等于把一份密钥字典写进日志）
11. 🔴 **写不进去就拒服务**：
    ```bash
    chmod -w $S/access.jsonl                                   # 🔴 chmod 的是【文件】
    curl -s -o /dev/null -w "%{http_code}\n" -u ":$KEY_A" $B/   # 期望 503（实测值）
    chmod +w $S/access.jsonl
    ```
    **必须是拒绝**，**不是**"看得到但没记上" —— 后者正是本单要消灭的状态。
    > ⚠️ 初版写的是 `chmod -w $S`（**目录**）—— 对目录去写权限**挡不住往已存在的文件追加**，
    > 它挡的是建/删条目。**Live 时因此返回 200，被误读成缺陷。**
    > 等价的更干净做法：起服务时 `TREVAL_CASES_ACCESS_LOG=/proc/nonexistent/x.jsonl`；
12. **效力边界自述**：`head -1 $S/access.jsonl` 含 `_note`，
    逐字写着**它不是哈希链、不能证明无人访问**
    （🔴 一份"访问记录"迟早被当成"审计证据"引用 —— 让它自己先说清）；
13. **隔离未破**：
    ```bash
    python -c "from treval.report_store import ReportStore;print(ReportStore('$S').list())"   # 期望 []
    ```

### 10.4 件 D + 记录页（验收 11、12）

14. `$B/access-log` 租户隔离 —— 🔴 **两条一起跑，缺一条就是空洞验证**：
    ```bash
    curl -s -u ":$KEY_ADMIN" $B/ >/dev/null                            # 先让 admin 留一行
    curl -s -u ":$KEY_A" $B/access-log | grep -c "platform-admin"      # 期望 0（看不到别人）
    curl -s -u ":$KEY_A" $B/access-log | grep -c "auditor-acme"        # 🔴 期望 ≥1（页面确实出了内容）
    ```
    > 🔴 **第二条是关键**：只查"搜不到别人"时，**"页面什么都没出"也会通过**。
    > **Live 时 `KEY_A` 已过期，返回的是访问页，于是这条空洞通过了。**
    > **先证明页面出了东西，再说它没出别人的东西。**
    `KEY_ADMIN` 查同一个页面 ⇒ **两个租户的行都能看到**；
15. 🔴 **不可枚举**：未知 / 过期 / 撤销三种输入的**状态码与文案逐字相同**（第 4 步已验其一）。

## 11. 为什么这一单值得做（一句留给以后的自己）

🔴 **"不长身份系统"是架构约束，不是"可以简陋"的许可。**
本单从头到尾没有引入一个新的身份概念 ——
它只是给已经存在的那把密钥补上**名字、期限和痕迹**。
**开源不等于半成品**：一份 operator_only 的绕过地图，
**谁看过必须有记录** —— 这条和登录框好不好看，不是一个量级的事。
