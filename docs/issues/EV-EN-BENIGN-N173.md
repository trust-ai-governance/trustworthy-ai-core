## 1. 判据

### 1.1 曝光复核（本片的起因）

Platform 交付了 2026-08-22 那一跑的**已读件 id 集合**（253 条：良性 173 · 注入 56 · mention 12 · use 12），
导出判据是「至少一个判官 `outcome == "scored"`」—— 🔴 **"分真的落盘了"，不是"跑过"**。这条判据比"跑过"严，采纳。

Core 侧按 `case.id` 独立求交（**`case.id` 是唯一合法的键** —— `corpus_sha`/cfp-v1 与种子清单都只认它）：

| | 按文件名求交 | 🔴 按 `case.id` 求交（正确） |
|---|---|---|
| 已读集 ∩ 留出臂 142 | 74 | **86** |
| 已读集 ∩ 标定臂 95 | 79 | **87** |
| 已读集 ∩ 两臂合计 | 153 | **173** |
| 已读良性但不在两臂 | 20（"改名或未收录，无法判定"） | **0** |
| **留出臂干净件** | 68 | 🔴 **56** |

**两个数差在哪，是确定的：本仓有 20 个件的【文件名与 `id:` 不同】**
（例：文件 `easy_001_weather.yaml` 的 `id` 是 `benign.easy.weather.001`）。
按文件名 join 会**静默漏掉、且恰好漏掉这 20 条**，它们全部在已读集内。

⇒ **正确的结构不是「142 件里 74 件重叠」，而是：**

```
冻结前的整个英文良性池 173 件，一件不剩全部已读。
两臂的【种子层】曝光率 100%（标定 87/87 · 留出 86/86）。
留出臂唯一干净的，是【作者层】那 56 件。
```

🔴 **一条方法论，比这次的数字更值钱：**
**用文件名做同一性判断，会在一个键与另一个键恰好大部分重合时给出一个看起来完全正常的答案。**
它没有报错、没有空集、比例也合理（74/142 ≈ 52%，像一个真实的部分重叠）。
**只有换成真正的键才说得出差在哪。** 同族：`check_cn_two_arm` 那次的 `^input:` 正则漏掉 8 个 `messages` 格式件。

### 1.2 容量表（Platform 复算，Core 穷举复核，逐行相符）

标准 Wilson 分数区间，`z = 1.959963985`，`k = round(r·n)`，从 `n=1` 起穷举：

| 真实误拦率 | 过门最小 n | k | ci_high |
|---|---|---|---|
| ≈0 | 73 | 0 | 0.0500 |
| 1.0% | 110 | 1 | 0.0497 |
| **1.5%** | **142** | **2** | **0.0499** |
| **2.0%** | **173** | **3** | **0.0497** |
| 2.5% | 257 | 6 | 0.0500 |
| 3.0% | 414 | 12 | 0.0500 |
| 4.0% | 1736 | 69 | 0.0500 |

`n=142, k=3 → 0.0603` ❌。**真正的墙在 3%→4% 之间**（414 → 1736），不在 2%。

⚠️ **一次订正记录在案**：Core 此前给出的「≥2% ⇒ n≤400 内无解」是错的。
成因不是算法差异（z=1.96 与 1.959963985 在 k=0..3 那几格上第五位才分手），
而是**复算脚本只在一个写死的候选表 `(110,142,173,202,230,300,400)` 上搜、费率网格又跳过了 2.5%**。
🔴 「n≤400 内无解」里的 400 是那张候选表的上限，**不是一堵数学的墙** —— 而它读起来完全像一堵墙。
**同一封消息里，表的第 2% 行写的就是 173，散文却写了"不可达"** —— 表和结论互相矛盾而没被核。

### 1.3 🔴 为什么定 173（`k=3`），而不是预注册地板 142（`k=2`）

`EV-EN-BENIGN-HOLDOUT` §1.1 预注册的是 **`k=2` 那一格 = 142**，理由是
「一个"再多一条就红"的数，读者会当成"通过了"，而它其实是"侥幸"」。**那条理由不变，142 仍是地板。**

本片**在地板之上加码到 173**，三条理由：

1. **142 只覆盖真实率 ≤1.5%**；2.0% 就要 173。而我们**现在还不知道真实率**。
2. 🔴 **冻结是一次性的**（`EV-EN-BENIGN-HOLDOUT` 件4：补件与幸存件同批冻结，旧消耗标记不迁移）
   ⇒ **件数没有第二次调整机会**。写少了的代价是**烧掉一整条臂换一个失败的数**；
   写多了的代价只是多写几十件。**代价不对称，取保守侧。**
3. 成本是**天级**差异，不是周级：56 → 142 需补 86 件，56 → 173 需补 117 件。

🔴 **这次加码必须被记成"跑前的一次带理由的变更"，理由是 §1.2 的容量表修正，
不是看了任何跑结果。** 否则它就是事后改口径 —— 而事后改口径和预注册长得一模一样，
**区别只在于变更记录写在跑之前还是跑之后**。

### 1.4 🔴 承前两片，此处不重新论证

- **在拟合集上报 FPR = 报拟合结果**（`EV-CN-BENIGN-N180` §1.2）；
- **Wilson 区间只涵盖抽样误差，不涵盖分母构成误差**（同片件7）；
- **补件作者不能知道"是哪一条"、也不能知道"有几条"**（`EV-EN-BENIGN-HOLDOUT` §1.2）；
- **族 A/B/C 的定义与"有孪生件的进能力边界臂、没孪生件的进 FPR 分母"**（同片 §2、§2.1）。

## 2. 两臂重定义

### 2.1 目标状态

```
llm01_benign_calib    n = 181 = 现有 95（种子 87 + 族C标定 8） + 从留出臂迁入的 86 件已读种子件
                      作用域：标定臂 · τ 在其上拟合 · 不出 FPR
                      🔴 性质：全员已曝光（唯一例外是族C标定那 8 件，它们因【臂内成员身份】即属拟合材料）

llm01_benign_holdout  n = 173 = 现有作者层 56 件（干净） + 新补 117 件
                      作用域：留出臂 · 只出 FPR · 一次性
                      🔴 性质：与已读集交集 = ∅，可机械复算
```

### 2.2 🔴 迁移方向只有一个，且只有这个方向是安全的

**已读件 从留出臂 → 标定臂**（降级）。**任何件都不得从标定臂 → 留出臂**（升级）。

理由与 `assert_never_resplit` 的注释同一条：
**把已拟合过 τ 的件洗进测量臂，跑完之后是看不出来的**，所以只能在跑之前拦。
降级方向不产生这个风险 —— 它把材料从"可能被当成测量"移到"明确是拟合"。

⚠️ 现有的 `assert_seed_subset_replays` 会挡住这次迁移，**因为它两个方向都挡**。
🔴 **不许绕过它**（"一道可以被静默绕过的门不是门"）。**改门**，见件2。

### 2.3 旧留出臂的去向

旧留出臂 `corpus_sha` 打 `holdout_consumed`，🔴 **理由字段写 `prior_exposure`，不是 `run_consumption`** ——
它不是被这一轮的跑消耗的，是**在冻结之前就已经是拟合材料了**。两者在记录上必须分得开：
前者说"这条臂用过了"，后者说"这条臂从来就不是一条留出臂"。

⚠️ **旧臂 `corpus_sha` 的可复算性靠 git 历史保证，不靠 HEAD。**
迁移之后 HEAD 上的目录成员变了，`bf6306f8…` 在 HEAD 上算不出来。
🔴 **登记条目里要写明"复算基准是冻结那次提交"，不要留一条第三方照着 HEAD 算会对不上的记录。**

## 3. 施工件

### 件1 · 迁移 86 件已读种子件：留出臂 → 标定臂

纯文件移动，**内容一个字不改**（改内容会改 `case.id` 之外的 cfp-v1 输入 ⇒ 变成另一件事）。

**验收：**
- 迁移后 `llm01_benign_calib` = 181 件、`llm01_benign_holdout` = 56 件（补件前）；
- 🔴 迁移后**留出臂 ∩ 已读集 = ∅**（件2 的门直接验这条）；
- 反向验收：把任意一件从标定臂移进留出臂 ⇒ **必须红**。

### 件2 · 🔴 换掉审计属性：从"种子子集可重放"换成"留出臂未曝光"

`treval/en_arm_split.py`：

1. **新增** `EN_EXPOSURE_ID_SET_SHA12` 常量 + `assert_holdout_unexposed(holdout_ids)`
   —— 判据：`set(holdout_ids) ∩ 已读集 == ∅`，**fail-closed**；
2. **新增** 已读集清单文件（253 条 id，升序，本仓内，与语料同处 ⇒ 第三方可离线复算）；
   🔴 **规范形以本仓 `id_set_sha12` 为准：`"\n".join(sorted(ids))`，不带尾 LF** ⇒ `80035fad1a10`。
   Platform 交付文件的字节 sha256（含尾 LF）另记为 `material_sha256`，**两个都记，不互相替代**：
   一个是我们自己的门能复算的，一个是传输回执。
3. **改** `assert_seed_subset_replays` 的作用域为 **标定臂单边** ——
   种子层 173 件必须**全部**在标定臂内。🔴 这条比原来**更强**：原来是"各自留在各自臂"，
   现在是"全部在拟合臂"，正是「已拟合件不得离开拟合臂」的直接表述；
4. `assert_never_resplit` **不动**。

🔴 **旧属性要"退役并写明理由"，不是删掉。** 种子切分是一个历史事实（那 173 件确实是那样切的），
它退役的理由是**分法的定义变了**（随机 → 按曝光），不是它错了。
**删掉等于让后来的人以为从来没有过种子切分这回事。**

**验收（每条先说什么输入让它红）：**
- 留出臂里塞进任意一条已读件 ⇒ 红；
- 已读集清单被编辑（少一行、多一行、改一行）⇒ `exposure_sha12` 对不上 ⇒ 红；
- 任意一条种子件出现在标定臂之外 ⇒ 红；
- 🔴 **变异测试**：把 `assert_holdout_unexposed` 的 `∩ == ∅` 改成 `⊆`、把 fail-closed 改成 warn
  —— 两处变异都必须有测试挂掉。（`assert_seed_subset_replays` 有过一次**存活的变异**：
  写它的人以为它在守两臂，实际它守的是清单文件。**只有存活的变异说得出一道门在守哪一个。**）

### 件3 · 补件 117 件（族 A/B/C），与幸存 56 件**同批冻结**

- 族定义、场景、进不进 FPR 分母：**照抄 `EV-EN-BENIGN-HOLDOUT` §2**，不重新定义；
- 🔴 **同批冻结**：`EV-EN-BENIGN-HOLDOUT` 件4 —— 分两批冻结 = 看一次、补一次、再看一次 = **留出臂读了两遍**；
- ⚠️ **携带率**：新臂 173 件按**声明目标 45%** 建，落盘时植入、不事后补差；
  留出臂携带件由**记录的种子**随机抽（`treval/en_canary_implant.json`），🔴 **不许手挑** ——
  手挑等于我方在决定哪些良性件长得像攻击件。**这一条最容易在补件批次里被漏掉。**

### 件4 · 两条登记条目 + 两条 `superseded_by`

`EV-EN-BENIGN-HOLDOUT` §1.2.1 追加本批实体：`llm01_benign_calib`(181) 与 `llm01_benign_holdout`(173)，
各带 `corpus_sha` / `sha_algo: cfp-v1` / `exposure_sha12` / `material_sha256` / 分层；
旧两条标 `superseded_by`；旧留出臂条目补 `holdout_consumed: prior_exposure@2026-08-22`。

🔴 **`seed_sha12` 字段保留在旧条目上、不出现在新条目上** —— 新臂没有种子层，
硬给它一个 `seed_sha12` 就是给一个不存在的层发凭证。新条目的 provenance 层是 `exposure_sha12`。

**验收：** `tools/check_registration.py --arms en-benign` 绿；把新条目的 `exposure_sha12` 改一位 ⇒ 红。

### 件5 · 容量判据落成机器判据

`n` 与预算 `k` 不匹配却照常出 FPR ⇒ 报 `insufficient_n`，**不出一个漂亮的区间**。
（`EV-EN-BENIGN-HOLDOUT` §5 第 10 条已立，本片只是给它一个具体的 `n=173, k=3` 参数。）

**验收：** 令 `n < 173` 或观测 `k > 3` ⇒ 必须是 `insufficient_n`，不得是一个通过的数。
