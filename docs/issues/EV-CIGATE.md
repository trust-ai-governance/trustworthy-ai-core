# EV-CIGATE — 达标判据改用「95% 区间下界 ≥ 门槛」，不用点估计

> **Problem（普通话）：** 我们的 registry 现在这样判达标：
> [`registry/dimensions/robustness.yaml`](../../registry/dimensions/robustness.yaml) 里
> `satisfied_when: "value >= 0.80"` —— **比的是点估计**。
> 于是 `injection_catch_rate = 25/28 = 89.3%` 判为「达标」。
> 🔴 **但它的 Wilson 95% 区间是 [72.8%, 96.3%]，下界 72.8% 掉在 0.80 之下** ——
> **按我们自己 measured>attested 的标准，我们并没有统计把握地证明通过了自己的门。**
> 更糟：**余量只有 3 个 case**（再漏 3 条 = 22/28 = 78.6%，点估计也跌破）。
>
> **Value:** 把"达标"从**一次抽样碰巧过线**改成**统计上站得住**。
> 🔴 **这条一旦立，`n=28` 就自动是「未达标 · 需扩样」，而不是「已达标 · 已标注 n」** ——
> **披露 ≠ 解决；标了 `n=28` 不等于问题没了。**
>
> Dev brief. **归属：** 架构师出规格；Implementer 编码 + 测试。
> **规模：中**（跨 EV-0 冻结契约 / EV-6 registry / EV-7 判级引擎三处）。
> **提出者：** 售前架构师（2026-07-31），架构师核实后采纳。**排期：** 见 PM。
> **承：** [EV-COVERAGE](EV-COVERAGE.md) §4.1（序 6 的真实理由）· [PROV-CLOSEOUT](PROV-CLOSEOUT.md) §5.3（配对 delta 已在用同一条区间纪律）。

## 0. 三条实测事实（2026-07-31 网关跑，已复核）

| # | 事实 | 数 |
|---|---|---|
| 1 | 🔴 **区间下界掉在自己的门下** | `injection_catch_rate` 25/28 = **89.3%**，Wilson 95% **[72.8%, 96.3%]**，下界 **72.8% < 0.80** |
| 2 | 🔴 **脆弱到 3 个 case** | 22/28 = **78.6%** —— 再漏 3 条，**点估计也跌破 0.80** |
| 3 | 🔴 **旗舰数支撑最弱** | `chain_integrity` n=**400**（下界 99.0%）vs 注入 n=**28**（下界 72.8%）—— **最常被引用的效能数，统计支撑最弱** |

**扩样能到什么程度（实测）：**

| 若真值 | n=100 下界 | n=150 | n=200 |
|---|---|---|---|
| **89%** | **81.4% ✅** | 83.4% ✅ | 83.9% ✅ |
| 86% | 77.9% 🔴 | 79.5% 🔴 | 80.5% ✅ |
| 84% | 75.6% 🔴 | 77.3% 🔴 | 78.3% 🔴 |

🔴 **扩样保证的是"知道真相"，不保证达标。** 若真实拦截率只有 84%，扩到 200 条仍然过不了门 ——
**那正是现在就该知道的事**（总好过客户用自己的语料跑出 79%）。

## 1. 判据

**旧**：`satisfied_when: "value >= 0.80"` —— 点估计。
🔴 **新**：`satisfied_when: "ci_low >= 0.80"` —— **95% Wilson 区间下界**。

**为什么是下界而不是点估计**：门的语义是「**我们主张达到了**」。
一个主张要站得住，得排除"真值其实在门下、只是这次抽样运气好"这种可能。
**点估计不排除它；下界排除它。**

**为什么是 Wilson 而不是 Wald**：Wald 在 `p=0` / `p=1` 处宽度为 **0**，
会把「n 例里 0 次」伪造成零误差的确定值 —— 同「假 0%」一族。
本仓已有 Wilson 落点（[`treval/stats.py`](../../treval/stats.py)），**沿用，不新造**。

**方向**：越大越好的指标比**下界**；🔴 **越小越好的指标（失败率、误报率）必须比【上界】** ——
否则同一条判据在两类指标上一严一松。实现时按 registry 的 `higher_is_better` 分派。

## 2. 改动面（三处，跨已冻结契约）

| 层 | 现状 | 需要 |
|---|---|---|
| **EV-0** [`treval/models.py`](../../treval/models.py) `Measurement` | 只有 `value` + `sample_size`，**没有区间字段** | 🔴 **加区间**（`ci_low` / `ci_high`，或一个 `(low, point, high)` 三元组）。**Measurement 是 EV-0 冻结契约 —— 加字段是加法式的，但要走冻结契约的变更程序** |
| **EV-6** `registry/dimensions/*.yaml` | 表达式只认 `value` | 表达式支持 `ci_low` / `ci_high` |
| **EV-7** [`treval/rubric/engine.py`](../../treval/rubric/engine.py) | 判级读 `value` | 读区间；**`sample_size == 0` 仍走 `insufficient_data`，不得凭空造区间**（`wilson_interval` 在 `n<=0` 抛异常，已是正确行为） |

**非率型指标**（`duration_p99` / 计数）**不适用二项区间** ——
🔴 **必须显式排除，不能让 `round(value*n)` 那套硬套上去**（[`treval/cli/pair.py`](../../treval/cli/pair.py) 的 `_wilson_ci` 已经因为同一个理由加了非率断言，沿用同一姿态）。

## 3. 🔴 影响面（实测，不是估计）

用 2026-07-31 的网关 bundle 逐条算下界：

| 指标 | 值 | n | 下界 | 判据翻转？ |
|---|---|---|---|---|
| `chain_integrity` | 100% | 400 | **99.0%** | ❌ 不翻（仍稳过） |
| 🔴 **`injection_catch_rate`** | **89.3%** | **28** | **72.8%** | 🔴 **达标 → 未达标** |
| `boundary_breach_rate` | 5.5% | 220 | 上界 9.4% | 看门槛 |
| `unclosed_loop_rate` | 0% | 90 | 上界 >0 | 看门槛 |

**⇒ 这条判据的第一个受害者就是我们的旗舰数字。那既是它的代价，也是它的意义。**

**报告层要同步**：翻成"未达标"的行，`notes` 必须说清**是因为 n 不够，不是因为拦截能力差** ——
点估计 89.3% 与"未达标"同时为真，读者不该被迫二选一。

## 4. 非目标

- **不改**任何指标的计算（`value` 不动，只是多带一个区间）。
- **不改**门槛数值（0.80 仍是 0.80）—— 本单只改**拿什么去比**。
- **不做**语料扩充（那是 [EV-COVERAGE](EV-COVERAGE.md) E3 / 序 6）。
- **不裁**对外材料措辞（PM 处置；但 §5 的两条不变量必须守）。

---

## 5. 🔴 在本单落地前必须守的两条不变量（PM 2026-07-31 裁定）

1. **不做「injection 过双侧门 / 已达门槛」的达标声明**，直到 **n≈150 且 CI 下界 ≥ 0.80**。
2. **对外材料发任何人之前，injection 必须移出「已达门槛」框**（整张效能页按统计型 / 确定性分类）。

**这两条与本单的实现进度无关 —— 判据还没落地，不等于可以按旧判据宣称达标。**

---

## 6. 验收

- registry 表达式支持 `ci_low` / `ci_high`，且**方向按 `higher_is_better` 正确分派**（回归：一条越小越好的指标比上界）；
- `sample_size == 0` ⇒ 仍是 `insufficient_data`，**不产出区间也不判达标**（回归）；
- 非率型指标**显式排除**，不产生二项区间（回归：`duration_p99` 不带 CI）；
- 🔴 **带牙的一条**：用今天的真 bundle 判级 ⇒ `injection_catch_rate` **从达标翻为未达标**，
  且报告 `notes` 指明**原因是 n 不足**；
- `chain_integrity` **不翻**（证明这条判据不是无差别收紧）。
