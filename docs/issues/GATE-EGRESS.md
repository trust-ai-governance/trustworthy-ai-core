# GATE-EGRESS — 内容出口门 + 工件自述级别

> **Problem（普通话）：** 上游已逐条实码核实并确认：网关审计日志里躺着的是
> **逐字、未脱敏的真实用户 prompt 正文**，而且**没有任何开关能关掉它**，
> **也没有按主体删除的机制**（详见 [UI-3 §14.A](UI-3.md)）。
> 于是两件此前只是理论的事，今天同时变成了活的：
>
> ① 🔴 **正文一直在我们的管线里流** —— `AuditEvidence.record` 就是整条解码后的记录
> （[wal_reader.py:102](../../treval/readers/wal_reader.py#L102)），
> **每一个被动指标手里都握着完整 prompt**。挡住它进产物的，
> **不是任何机制，是"到今天为止没人写那行代码"**。
> ② 🔴 **我们自己有一把能读它的工具** —— `tools/wal_dump.py --decode/--join`
> 把整条记录打成可读 JSON，**而输出里一个字都没说这是什么级别的东西**。
>
> **Value:** 两件都是把**运气**换成**机制**。
> ①把"没人写"变成"写不出去"（CI 拦）；②把"大家应该知道"变成"工件自己说"。
> 🔴 **这两条互不替代**：①管我们**自动产出**的东西，②管人**手动导出**再粘贴的东西。
>
> Dev brief. **归属：** Implementer 编码 + 测试。**规模：小-中。**
> **前置：** 无。**与 [UI-3](UI-3.md) 无依赖，可并行下发。**

## 0. 两件分别防什么（别合并理解）

| | 防的路径 | 出错的是 | 手段 |
|---|---|---|---|
| **件一 内容出口回归** | 我们**没打算输出**的正文，漏进了自动产出的工件 | **机器**（一行代码） | **测试**（CI 拦） |
| **件二 `wal_dump` 自述** | 我们**打算输出**的正文，被贴到了不该贴的地方 | **人**（一次粘贴） | **自述**（工件自带级别） |

🔴 **过滤器解决不了任何一件**：件一里没有可过滤的入口（正文本来就在对象上），
件二里工具读的是本地文件、不传参数就绕过了。

## 件一 — 内容出口回归

### 1.1 今天靠什么挡着（实核）

| | 状态 |
|---|---|
| `AuditEvidence.record` 携带整条解码记录 | ✅ 是（[wal_reader.py:102](../../treval/readers/wal_reader.py#L102)）—— **正文在每个指标手里** |
| 案级契约 Tier 0 有没有正文字段 | ✅ 没有 —— `build_cases` 只写指针与判定 |
| 探针失败时错误文本进不进契约 | ✅ 不进 —— 只留 `verdict="errored"` 这个词 |
| `collect` 的 warning 进不进 bundle | ✅ 不进 —— 走 stderr（[collect.py:477](../../treval/cli/collect.py#L477)） |
| **有没有一条测试把上面四条钉住** | ❌ **一条都没有** |

🔴 **⇒ 四条全是"今天恰好如此"，不是"不可能不如此"。** 这正是本件存在的理由。

### 1.2 会怎么破（三个具体场景）

**场景 A — 调试字段回流（最现实）**
有人查 `unclosed_loop_rate` 为什么多算一条，顺手写
`Measurement(..., detail=f"unmatched: {ev.record}")`。
这条进 `bundle.json` → 进报告库 → 被 `/report.json` **逐字服务**
（README 承诺 "stored bytes byte-for-byte"）→ 客户手上那份副本里也有。
**一次调试提交 = 一份永久扩散的用户 prompt。**

**场景 B — 上游异常文本借道**
上游的审计错误文本是异常的 `repr()`，**可能嵌入正文片段且不受长度帽约束**（上游主动提示）。
今天 Core 没有 surface 它的路径——**但这是巧合**。哪天加一列"这条为什么失败"，片段就跟着走。

**场景 C — 派生描述**
上游判官对用户 prompt 的**自然语言描述**默认全量上盘。
它**不长得像正文**，所以最容易被当成"安全的元数据"取出来放进报告。

### 1.3 🔴 为什么必须"按值双查"

只按字段名查是**空检查**：场景 A 里那个字段叫 `detail`，不叫 `params_indexed`，名字匹配对它返回 True。

**⇒ 两道一起上：**

| 道 | 做法 | 抓得住 | 抓不住 |
|---|---|---|---|
| **名字** | 断言产物里不出现 `params_indexed` / `params_raw` / `response_body_preview` / `response_body_sha256` / `hint_variables` / 审计错误文本字段 **这些键名** | 直接搬字段 | **改名字**（场景 A） |
| 🔴 **值（哨兵）** | 用一条**埋了唯一串**的正文跑完整管线，断言该串在**每一份产物里出现 0 次** | 改名字、拼接、截断、嵌进 f-string | 编码变换（base64/hash）——见 §1.5 |

> **纪律出处**：说不出什么输入能让检查返回 False，这个检查就是空的。
> 上一轮那个 `'ci' in inspect.getsource(...)` 就是这么假通过的（`'ci'` 是 "de**ci**sion" 的子串）。

### 1.3.1 🔴 哨兵必须种进 **WAL 记录的内容字段** —— 否则本件漏掉自己点名的那条通道

**第一版实现只把哨兵种在主动侧**（`ProbeResult.response_text` / `raw_response`），
**WAL 记录的 `params_indexed` / `params_raw` 是空的**，而且 **`build_products` 一个被动指标都没跑**。
实测的后果：

```
① 哨兵所在: ['response_text', 'raw_response']      ← 只在主动侧
② WAL 记录的 params_indexed: {}   params_raw: b''  ← 🔴 全空
③ 模拟一个被动指标把 params_indexed f-string 进 notes
④ 门看到了吗: ❌ 没有 —— 两道都没红
```

**两道全漏，各有各的原因：**

- **值那道**：哨兵从没进过 `params_indexed`，泄漏出去的是空 `{}` —— 没有可匹配的串；
- **名字那道**：泄漏的是 dict 的**内容**，键名 `"params_indexed"` 根本不出现在产物里。

🔴 **而 §1.1 论证本件必要性时，用的正是被动侧的理由**
（"`AuditEvidence.record` 就是整条解码记录，**每个被动指标手里都握着完整 prompt**"）。
**论证用被动侧，覆盖只做主动侧 —— 这条门证明的比它宣称的窄。**

**⇒ 硬性要求（缺一即本件不算完成）：**

1. 构造 `AuditEvidence` 时，把哨兵种进
   `record.invocation.params_indexed["messages.0.content"]` **与** `record.invocation.params_raw`
   —— **那才是生产记录的真实形状**；
2. `build_products` 必须**跑一遍被动指标**（`chain_integrity` / `unclosed_loop_rate` /
   `duration_p99` / `terminal_error_ratio`），让它们的 measurement 也进 bundle 与 report；
3. 带牙：把某个被动指标的 `notes` 改成 f-string 进 `params_indexed` ⇒ **值那道必须红**。

### 1.4 覆盖面（产物清单，一个都不许漏）

哨兵跑一次，断言它不出现在：

1. `collect` 产的 **measurement bundle**；
2. `report` 产的 **成熟度报告**（human 与 JSON 两种渲染）；
3. **自包含 bundle** 与**报告库里存下的字节**；
4. **案级契约 Tier 0**（`--cases-out`）；
5. `pair` 产的 **delta**；
6. **覆盖率报表**；
7. 🔴 **stderr / stdout** —— 它不是文件，但它进 CI 日志、进被粘贴的终端输出。

**Tier 1（`--include-response-content`）显式排除**：它**本来就该含正文**，
那是 `internal_handoff` 的定义。🔴 **测试要断言它确实含**——
否则哪天 Tier 1 悄悄不含了，我们会以为是安全改进，其实是功能坏了。

### 1.5 诚实边界（写下来，别让它冒充全覆盖）

- 哨兵查的是**逐字出现**。若某条路径把正文 **hash / base64 / 摘要**后输出，哨兵**抓不住**。
  ⇒ `response_body_sha256` 这类**按名字**那道拦；**新出现的派生形式拦不住**，
  这是本件的已知残余，**写进文档，不假装没有**。
- 本件证明的是"**我们跑过的这条路径**没漏"，不是"任何代码都不可能漏"。

### 1.6 验收（带牙）

- 哨兵正文跑一遍 ⇒ §1.4 的 1–7 里**出现 0 次**；
- 🔴 **被动通道有覆盖**（§1.3.1）：哨兵在 `params_indexed`／`params_raw` 里，且**被动指标真跑过**
  —— **带牙：让一个被动指标把 `params_indexed` 写进 `notes` ⇒ 值那道必须红**；
- 🔴 **带牙一**：往任一指标里加一句 `detail=<正文>` ⇒ **测试红**；
- 🔴 **带牙二**：把某个正文字段**改名**再放进产物 ⇒ **值那道仍红**（证明双查不是摆设）；
- 🔴 **带牙三**：让 Tier 1 不再输出正文 ⇒ **测试红**（§1.4 末段）；
- 门与既有三门**同构**：命中打印 `产物 + 命中位置 + 为什么`，exit 1，CI 里跑，
  **CI step 带 `PYTHONPATH`**（语料门踩过这个坑）。

## 件二 — `wal_dump` 自述级别

### 2.1 它不是 bug

`tools/wal_dump.py --decode` 打印正文**是它的本职** ——
docstring 写着 *"Compensates for the binary WAL format being unreadable to grep"*。
权限门是**"你得能读到那个 WAL 文件"**，和 [EV-R2 P2-4](EV-R2.md) 依赖的是同一道门。**这条不动。**

🔴 **问题在输出离开终端之后。**

**场景**：线上一个请求被拦，值班的人跑
`python tools/wal_dump.py <wal> --join --from 1200 --to 1210`，
得到一段结构规整的 JSON —— **看起来就是诊断数据** —— 于是贴进工单 / 贴给厂商支持 / 贴进群里。
那段 JSON 里是**另一个租户的真实用户 prompt 全文**
（`params_indexed` 逐字、`params_raw` 64 KiB、`response_body_preview`，
[wal_dump.py:85](../../tools/wal_dump.py#L85)），
而**屏幕上没有一个字**告诉他这件事。
且按上游提示，`--join` 恰恰是那个**把身份和响应预览拼到一起**的操作。

### 2.2 这一家里只有它不自述

| 工件 | 自述了吗 |
|---|---|
| 案级契约 | ✅ `disclosure_class=operator_only` |
| `treval cases verify` | ✅ 四行作用域声明，不可关 |
| 案级页（[UI-3](UI-3.md)） | ✅ 常驻横幅 |
| **`wal_dump --decode` / `--join`** | ❌ **零** —— 而它的载荷**最敏感** |

### 2.3 范围

**`--decode` / `--join` 输出前打印一段头部**（stderr，**不污染可 pipe 的 stdout**）：

- 这份输出**含未脱敏的请求正文**（每条 message content 逐字）；
- 按 EV-R2 词表属 **`internal_handoff`** —— **勿贴入工单、群聊、厂商支持或任何对外材料**；
- 若这是**生产** WAL，一个段文件里**交织多个租户**，你看到的可能不止你要查的那一个；
- docstring 与 `--help` 同步这三句。

**默认 dump（不解码）不加头部** —— 它只打字节预览与哈希，不是同一类东西。
🔴 **级别跟着内容走，不跟着工具走**，别一刀切。

### 2.4 🔴 不加 `--tenant` 过滤器

对一个读**本地文件**的调试工具，过滤器**不是边界** —— 不传就没了。
它加不了任何遏制，**却看起来像遏制**。

**先例（我们自己判过的同一个病）**：[GATE-CONSISTENCY 件一](GATE-CONSISTENCY.md) 里
`[GATED]` 只是渲染标签、代码里没有阈值比较，当时的裁定是
**"一个不判定的 GATED 标签比没有标签更误导 —— 它让读者以为有人在判"**。同一条，不重犯。

### 2.5 验收

- `--decode` / `--join` ⇒ 头部三句出现在 **stderr**；
- 🔴 `wal_dump --decode <wal> > out.json` ⇒ **`out.json` 里没有头部**（stdout 仍然可 pipe、可 diff）；
- 默认 dump ⇒ **无头部**；
- `--help` 与 docstring 含同样三句；
- 🔴 **不新增 `--tenant`**（回归：断言该参数不存在——防止"顺手加个过滤器更安全"的好意）。

- **不改** `wal_dump` 的输出内容与退出码（它的本职不变）；
- **不加**任何过滤器 / 脱敏 / 掩码（§2.4；脱敏在上游，不在阅读端）；

## 6. 与相邻单的关系（三层同一威胁，谁也不替谁）

| | 挡什么 | 时机 |
|---|---|---|
| [UI-3 §14.B-3](UI-3.md) | **别建那个东西** —— 不要有存生产逐请求数据的库 | 设计期 |
| **本单件一** | 就算不建库，**正文也不许进工件** | 构建期（CI） |
| **本单件二** | 手动导出的正文，**至少自带级别** | 使用期 |

🔴 **件一不是 B-3 的代理**：一个"生产逐请求库"完全可以照案级库的样子做 ——
**只存指针、零正文**，那样件一一条都不会红。
**B-3 挡的是"多一个删不掉的数据持有者"，件一挡的是"正文进工件"。两者正交。**

**串起三条的那一句**：上游确认**无按主体删除**（哈希链使选择性擦除被设计成不可能，
最粗可用单位是整段，而一段交织多租户）⇒ **任何一份副本都是永久的。**
所以三条在回答同一个问题：**这份删不掉的东西，还能扩散到几个地方？**
—— **B-3 管库 · 件一管工件 · 件二管剪贴板。**
