# UI-3 — 案级证据下钻：Tier-0 复算服务

> **Problem（普通话）：** 报告说"注入拦截率 89.3%"，**没人能自己把这个数加回来**。
> [EV-R2](EV-R2.md) 已经把逐案结果做成了可复算的契约，但它今天只是一个**文件**——
> 要看它，得有人把 `/tmp/cases.json` 发给你。
> 🔴 **而这个文件是绕过地图**：`(attack_technique, verdict ≠ hard_blocked)` 这一对本身就在说
> "这条手法能过这个网关"，零正文也一样。所以它**不能靠传文件流通**，也**不能塞进对外报告服务**
> —— 报告库今天已经在门口拒收它（[report_store.py:99](../../treval/report_store.py#L99)）。
>
> **Value:** 给这份数据一个**它自己的**服务：租户绑定、结构隔离、机械披露门，
> **页面的主体不是"看一眼有哪些用例"，而是"当场把 89.3% 加回来"。**
> 🔴 **这是"measured > attested"用在我们自己身上的最后一步** ——
> 在这之前，89.3% 仍然是**我们报的一个数**；在这之后，它是**读者能自己验的数**。
>
> Design brief. **归属：** 架构师定形 → Implementer 编码 + 测试。
> **规模：中-大**（[EV-R2 §6.2](EV-R2.md) 已上调）。
> **前置：** 无外部依赖（EV-R2 契约已合并；P2 五条已裁）。

## 1. 🔴 先拆：UI-3 其实是两件事，只有一件今天能做

Backlog 里 UI-3 写的是「证据下钻 = 重开 [EV-W1 D3](EV-W1.md) 撤销的 `/evidence`」。
**核完源码后必须拆开** —— 那一句把两个不同的下钻并成了一个：

| | 下钻到什么 | 样本是什么 | PII 面 | 今天能不能做 |
|---|---|---|---|---|
| **UI-3a**（本单） | **用例级**（`case_id`） | **合成语料**（`corpus/` 是公开的） | 🔴 **无新增**——行里零正文，服务永不读 WAL（§7） | ✅ **能** |
| **UI-3b**（不做，登记） | **请求级**（`request_id`） | **真实生产流量** | 🔴 **真 PII 面**，须重做威胁模型 | ❌ 依赖 **#6 生产被动路径** |

🔴 **这是"一个字段不扛两件事"用在一条路由上。**
`/evidence` 这个名字同时扛了"合成用例的判定"和"真实请求的正文"，
两者的**血缘、分母、PII 面全不同**。本单只做 UI-3a，**并且不叫它 `/evidence`** ——
EV-W1 D3 的两条守卫（无 `/evidence` 路由、app 不 import active-eval）**保持绿**，
[test_web_report.py:353](../../tests/test_web_report.py#L353) 一行不动。

### 1.1 「#6 生产被动路径」是什么，以及为什么 UI-3b 卡在它上面

> ✅ **已定稿（2026-08-04，上游逐条实码核实后）** —— 本节措辞**不用改**：
> `request_id` 解引用到的是**正文级 PII**，不是元数据关联 PII。
> **UI-3b「须重做威胁模型 + 登记延后」成立。** 依据与三条 Core 侧裁定见 **§14**。

> **#6 一句话**：让 `treval` 能对**真实生产租户的流量**出报告 ——
> 而不是像今天这样，只对**我们自己发的探针**出报告。
> 排期条目：[EVAL_ISSUES §#6](../EVAL_ISSUES\(WIP\).md)。它**没有独立设计文档**，
> 公开侧的接缝落点是 [`treval/protocols.py::AuditEvidenceReader`](../../treval/protocols.py#L20)。

🔴 **今天这个仓里不存在任何一条真实用户的请求。** 两条管线的样本都是我们自己造的：

| | 样本从哪来 | `request_id` 指向什么 |
|---|---|---|
| **主动**（`tools/eval_report.py`） | 我们发的合成语料探针 | 我们自己的探针 |
| **被动**（`treval collect`） | **评测租户自己那份 WAL** —— 也就是刚才那批探针的记录（[collect.py:13](../../treval/cli/collect.py#L13) *"Production-scoped passive reads land later"*） | 我们自己的探针 |

**#6 就是把被动侧接到生产租户的 WAL 上**（挂 `AuditEvidenceReader` 这条被动缝，
**不是** EV-FWD 的 `ProbeResult` 缝），范围里含**租户隔离**与**独立的 PII 面评估**。

**⇒ 这就是 UI-3b 的依赖的真实性质**，它不是"缺一个功能"：

> 🔴 **`request_id` 今天指向我们自己的合成探针；#6 落地的那一刻，同一个字段开始指向真实用户的请求。**
> 请求级下钻**在 #6 之前没有消费者**（点进去只能看到我们自己发的东西，而那件事 UI-3a 已经在
> 用例级用更好的键做了），**在 #6 之后才第一次有 PII 面**。
> **消费者与风险同时出现** —— 所以它必须跟着 #6 走，不能"顺手做了"。

> **UI-3b 的触发条件（登记，不预建）**：#6 落地 **且** 有人真的需要从报告点进请求级证据。
> 到那天它要重做的不是 UI，是威胁模型 —— [EV-R2 P4](EV-R2.md) 已经登记过同一件事。

🔴 **每一条都必须能指出"什么输入会让它 FAIL"** —— 否则它是空检查。

| # | P2 条件 | 机械落点 | 什么输入让它 FAIL |
|---|---|---|---|
| **1** | 存储物理/逻辑隔离 | **`treval/case_store.py`** 独立模块 + 独立目录 + 🔴 **独立 index 文件名**（§5.3）+ 独立 app（默认不挂载，§4.3） | 把案级契约喂给 `report_store.write_bundle` ⇒ 拒（**已在**）；把 EV-R1 报告喂给 `case_store` ⇒ 拒（**要加**，对称的第二扇门） |

| **3** | `disclosure_class` 必填 + fail-closed | ingest 门（§5.2） | 缺 class ⇒ 拒（**不是**默认 public）；`internal_handoff` ⇒ 拒 |

| **5** | 存在理由锚在复算 | 复算面（§6）+ 每个新字段的准入问句 | 加一个答不出"它服务于复算吗"的字段 ⇒ review 打回 |

> **两个"披露门"不是一回事，别串**：
> `tools/check_disclosure.py` 管的是**公开仓里不许出现的内容**（`DISCLOSURE_POLICY.md` 五类）；
> 本单的 `disclosure_class` 门管的是**一份数据能进哪个服务**。同名不同物。

## 3. 🔴 承重决定：租户由**凭据**推出，不由 **query 参数**选

### 3.1 冲突

| | 说了什么 |
|---|---|
| **EV-W1 D4**（已落地） | *Core 没有身份系统，EV-W1 **不许**长出一个*；`?tenant=` 是**选择器**，per-viewer ACL 是**非目标**，多租户部署须自己前置 authz |
| **EV-R2 P2-2**（PM 已裁） | *只对拥有该网关的租户服务，**绝不跨租户***，且**五条都是机械的** |

**对报告来说** D4 的姿态是站得住的：报告是租户自己的治理成绩单，泄露是商业敏感。
**对绕过地图来说站不住** —— 一个共享 token 就能看到**每个**租户"哪条手法能打穿"。
P2-2 明写这是机械条件，"文档里说清楚"不满足它。

### 3.2 🔴 "admin 看全部、租户看自己"是对的 —— 但 Core 里没有"登录"这回事

这是正常的产品形状，而且**正是 Platform 的形状**（它有身份系统、租户、控制台、RBAC）。
**Core 不是。** 核过源码：`treval/web` 今天的认证是**一个共享 bearer token**
（`TREVAL_WEB_TOKEN`，[app.py:91](../../treval/web/app.py#L91)）——
**没有用户表、没有会话、没有角色**。"谁登录了"这个问题在这个进程里**无法回答**。

⇒ 要做"admin/租户用户"语义，得先在开源引擎里长一个自研 authz，**去守一份绕过地图**。
D4 当初禁的就是这个，理由今天仍然成立。

### 3.3 三条路，选第三条

| | 做法 | 判 |
|---|---|---|
| (a) | 长 per-viewer ACL（用户表/会话/角色） | ❌ **违反 D4** —— Core 变门户；自研 authz 守绕过地图是负债 |
| (b) | 沿用报告服务姿态：一个共享 token + `?tenant=` 选择 | ❌ **一个 token = 全部租户的绕过地图**；P2-2 要的是门 |
| (c) | 🔴 **token → tenant 映射**：租户由凭据推出 | ✅ **选它** |

**(c) 怎么做**：一份小映射（`TREVAL_CASES_TOKENS` 指向 `{"<token>": "<tenant_id>"}`，
值可为 `"*"` = 看全部 —— **这就是"admin"**）。

- **`?tenant=` 不作为授权输入存在**：你看到什么由**凭据**决定，不由 URL 决定；
- token 作用域为 A，请求 tenant=B ⇒ **403**（🔴 **不是**静默回落到 A —— 静默回落会让越权请求
  看起来成功过，正是"0% 与看不到同形"那一类错误）；
- token 为 `*` ⇒ `?tenant=` 才作为**已授权范围内的选择器**生效；
- 🔴 **`*` 必须是映射里的显式一行，永不是缺省**。

**实现细则（免得实现时各自发挥）**：

| | 定 |
|---|---|
| 凭据怎么递 | 三条并存：`x-treval-token` 头 · `Authorization: Bearer <token>`（[app.py:94](../../treval/web/app.py#L94)）· 🔴 **HTTP Basic**（username 忽略，password = token） |
| 🔴 **为什么必须有 Basic** | **浏览器递不了自定义头** —— 只有前两条时，复算面**在浏览器里根本打不开**，而复算面是这一单的主体。Basic 是浏览器原生、**不进 URL、不进历史**、无需登录页与 cookie 逻辑。**仍不是身份系统**：没有用户表/会话/角色，`scope_for_token` 一个字不改，只是同一个共享密钥换个递法。**不采用 `?token=`**（会进浏览器历史、访问日志与 Referer） |
| 🔴 **401 必须带挑战头** | `WWW-Authenticate: Basic realm="treval cases (operator_only)"`。**没有它，Basic 只对 `curl -u` 有用**（curl 主动发凭据），**浏览器永远不弹框**。**这条是"curl 之外还能进"的充要条件。** |

### 3.4 🔴 更正：人的入口是**访问页**，不是浏览器弹框（PM，2026-08-05）

**又一次同样的毛病，得说清楚**：上一版我选 Basic，是因为它**满足安全属性且代码最少**。
但落到人手里是"弹一个框，用户名留空，密码粘一串 token" —— **那不是产品，是实现细节漏到了界面上。**

🔴 **本单我犯了三次同一个错**（§4.4 的砸品牌、无导航、这条弹框）：
**每次都挑了"满足属性、代码最少"的做法，把人的体验当成溢出物。**
单条都说得通，**合起来不是一个能交付的东西**。

**⇒ 定版：一个真正的访问页，而且仍然不长身份系统。**

| | 定 |
|---|---|
| `GET /` 无凭据 | 渲染**访问页**：与主应用同 chrome（logo/字阶/色板）· 说明这是什么服务 · **写明 `operator_only`** · 一个输入框「访问密钥」 |
| 提交 | `POST /session` → 校验 token 映射 → 种 **HttpOnly · SameSite=Strict · Path=/**（https 下加 `Secure`）cookie → **302 回原页** |
| 退出 | `POST /session/logout` 或一个「退出」链接清 cookie |
| 🔴 **为什么这仍不是身份系统** | 没有用户表、没有会话存储、没有口令哈希、没有角色继承。**cookie 里就是同一个共享密钥**，`scope_for_token` 一个字不改 —— 只是换成浏览器保管的递法 |
| 🔴 **为什么不是 `?token=`** | 进历史、访问日志、Referer。**cookie 不进这三处** |
| Basic 的去向 | **保留，但降级为 `curl -u` / CI 的通道** —— 不再是人的入口 |

🔴 **这条改动要同时改验收 10 —— 而且是改判据本身，不是给它开例外。**
验收 10 原文是"全路由 POST/PUT/DELETE/PATCH ⇒ 405"，而它的**本意**是
[EV-W1 D5](EV-W1.md) 的"**不评分、不重算、不修改任何数据**"。
**我把"不写数据"写成了"没有 POST"这个便宜代理，现在这个代理在逼出坏产品。**
（同 [GATE-CONSISTENCY 件一](GATE-CONSISTENCY.md) 判 `[GATED]` 标签那次：**代理不等于判据。**）
新判据见验收 10。
| 映射从哪来 | `TREVAL_CASES_TOKENS` = **一个 JSON 文件路径**。🔴 **不接受 inline 环境变量**——token 会出现在进程表与 shell 历史里 |
| 映射文件读不了/不是对象/值不合法 | **拒绝启动**（fail-closed），报文指名文件与那一行 |
| `*` token + 库里 >1 租户 + 没给 `?tenant=` | 🔴 **不默认挑一个** —— 返回租户清单让人选（`GET /`）；`/run`、`/cases.json` 缺 `?tenant=` 时若 `key` 唯一即可解析，否则 **400 并说明要带哪个参数** |
| 作用域 token + 请求里带了 `?tenant=`（值等于自己） | 放行（幂等），**不等于自己 ⇒ 403** |

> **这不是身份系统**：没有用户、没有会话、没有口令、没有角色继承 ——
> 就是 Core 已有的共享密钥模型**加上作用域**。
> 而它把 `?tenant=` 从**选择器**变成了**边界**：那正是 P2-2 要的机械性。

🔴 **不假设任何外部身份系统**（PM 更正，2026-08-04）：Core **可独立部署**，客户**不一定有 SSO**。
token 映射本身就是完整机制 —— 它**不是**"等 Platform 前置"的占位。
若确有上游前置（Platform 控制台或客户自己的 authz），那是**加分项，不是前提**：
本服务在没有任何前置的裸部署下，作用域也必须成立。

## 4. 形状：独立 app，**默认不可达，显式可挂载**

### 4.1 🔴 更正：承重的不是"进程分开"

**先更正我自己的一处推导**：早先写的是"两种姿态不能共存于一个进程 ⇒ 必须分进程"。
不严谨 —— 承重的是 §3.3 那条（**租户由凭据推出**）。分进程只是达成它的**手段之一，而且是贵的那个**
（N 个租户 N 个进程）。凭据作用域一旦成立，进程分不分就变成了**产品判断**，不再是安全推论。

### 4.2 那么还分不分？分 —— 但理由换成一条更硬的

🔴 **报告与案级来自两条不同管线的两次不同跑，不是一个对象的两个视图。**

- 成熟度报告走 `treval collect → report`；案级契约走 `tools/eval_report.py --cases-out`；
- 二者**从来不是同一次跑**（今天没有任何命令同时产出两者）；
- [EV-R2 §9.1](EV-R2.md) 已经明令：**两次跑 = 对同一个统计量的两次抽样**，
  跨跑比对会**假报"分叉"** —— 这正是 EV-CIGATE F1 那次误诊。

**把两者并进一个界面，等于在 UI 上邀请读者做这件被明令禁止的事。**
（哪天 `collect` 能在**同一次跑**里同时产出报告与案级契约，这条理由就消失，届时再合并。）

#### 4.2.1 🔴 更正：导航项要有 —— 藏功能不是缓解（PM，2026-08-05）

上一版由上面这条推出了"侧栏不放案级入口，只能靠 URL 进"。**推过头了。**

🔴 **"不放链接"不是唯一的缓解手段，而且是最差的那种** ——
它没有消除跨跑误比的风险，只是**把风险连同功能一起藏起来，让用户自己去猜**。

**⇒ 链接照放，风险用"说清楚"来消：**

| | 定 |
|---|---|
| 位置 | 报告页与详情页的**左侧栏**，与 Dashboard / 报告详情并列 |
| 🔴 **文案** | **「用例明细」**，副标题 **「逐条用例的判定 · 可自行复算聚合数」**。**不叫"下钻"** —— 那是 drill-down 的直译、是行话不是人话（issue 编号 UI-3 保留，**对外文案全改**） |
| 🔴 **落地页必须自报跑次身份** | 顶部一行：`本页来自另一次评测运行 · <generated_at_ns 可读时间> · corpus_sha=<前 8 位>`，并**明写**"与左侧报告**不是同一次跑**，两者的同名指标是**两次抽样**，不可直接相减" |
| 未挂载 / 未配置案级服务时 | 导航项**不显示**（不是显示一个点了报错的死链） |

> **规则**：**风险靠"把口径写在页面上"消，不靠"让人找不到"消。**
> 后者只是把架构师的顾虑变成了用户的困惑。

### 4.3 🔴 单入口是**配置项**，不是"去找个东西前置它"（PM 更正，2026-08-04）

**先更正第二处**：上一版把单入口的出路写成"Platform 或谁前置它"。**不成立** ——
Core 可独立部署，客户不一定有 SSO。**独立部署的 Core 自己就得能单入口。**

🔴 **真正的轴不是"几个进程"，也不是"谁前置"，是 opt-in／默认不可达 **vs** 永远在场。**

| 姿态 | 怎么配 | 判 |
|---|---|---|
| **默认**（不配任何东西） | 8090 报告 + 8091 案级，两个端口 | ✅ 裸 Core 独立部署即成立 |
| **单入口**（可选） | `TREVAL_CASES_MOUNT=/cases` ⇒ 报告 app 在 8090 下挂载案级 app | ✅ **同样是裸 Core 自己就能做**，不需要任何外部身份系统 |
| 永远在场 | —— | ❌ 案级数据不得在未表态的部署里可达 |

**谁读这个变量**：`treval/web/__main__.py`（报告服务的入口）——
设了就 `app.mount("/cases", create_cases_app())`，没设就什么都不做。
🔴 **`create_app()` 本身永不挂载** —— 库函数保持纯粹，挂载是**部署姿态**，只在入口表达。
（否则任何 `import` 了 `create_app` 的测试/嵌入都会莫名其妙带上案级路由。）

**两种姿态下 §3.3 的凭据作用域完全一致** —— 挂载不改变授权：
挂载后 `/cases/*` 仍只认 `TREVAL_CASES_TOKENS`，🔴 **`TREVAL_WEB_TOKEN` 永远打不开 `/cases/*`**
（挂载的是 app，不是路由：子 app 带着自己的依赖，父 app 的 token 不下渗）。
**这条要有专门的回归**：拿报告 token 请求挂载后的 `/cases/` ⇒ **401**（验收 14）。

> **默认拒绝、显式组合** —— 和这个仓其他地方是同一条纪律。
> 它也回答了"为什么要单独出一个 web 界面"：**不是不给你单一入口，是不把它做成默认。**

| | 报告服务（既有，不动） | 案级服务（本单） |
|---|---|---|
| 模块 | `treval/web/app.py` | **`treval/web/cases_app.py`**（可挂载） |
| 存储 | `treval/report_store.py` | **`treval/case_store.py`** |
| 租户 | 多租户选择器（`?tenant=`） | 🔴 **凭据作用域**（`?tenant=` 非授权输入） |
| 端口 | 8090 | **8091** |
| Token | `TREVAL_WEB_TOKEN`（单一） | 🔴 **`TREVAL_CASES_TOKENS` 映射**（§3.3） |
| Token 缺省 | 无 token = loopback 姿态 | 🔴 **无映射 = 拒绝启动**（fail-closed，绝不"无 token 即放行"） |
| 读 WAL | 否 | **否**（§7） |
| 能跑探针 | 否（守卫已在） | **否**（守卫要加，§5.1） |

**路由**（全部只读，无 POST/PUT/DELETE/PATCH，无 `/evidence*`）：

```
GET /                → 凭据作用域内的历次跑，最新在前（`*` token 才见到多个租户）
GET /run?key=        → 🔴 复算面（§6）—— 这一单的主体
GET /cases.json?key= → 存储的字节，逐字（🔴 主承重物，§6.1）
/static/*            → 复用既有 CSS
```

`key` = 内容摘要（沿用报告库的内容寻址；案级契约没有"窗口"这个口径，摘要就是它的身份）。
🔴 **`key` 也要过作用域**：摘要不可猜，但**不可猜不是授权** —— 取到记录后仍须比对
`record.tenant_id` 与凭据作用域，不符 ⇒ **404**（不是 403：对越权者连"存在"都不该确认）。

**每个响应带** `Cache-Control: no-store` + `X-Robots-Tag: noindex, nofollow`。
**每个页面顶部一条常驻横幅**：`operator_only · tenant=<该记录的租户> · 租户内部物，勿贴入工单或对外材料`。
🔴 **理由**：P2-1 防的原话是"第一次贴进工单就出去"。
页面**会**被截图；截图**会**被贴。**横幅上的那行字**是唯一跟着截图走的东西。

### 4.4 🔴 更正：分级靠**组件**，不靠**另起一套皮**（2026-08-05）

**本节推翻我自己上一版的一句话。** 上一版写的是：

> ~~"案级页的头部配色/标识必须与报告页**明显不同** —— 同样的 chrome 就是同样的截图。"~~

**这句错了，而且错在一个可以指名的地方：它从一个安全顾虑，伸手去改视觉身份 —— 那不是它该动的杠杆。**
后果是可预见的：一个只被告知"要明显不同"的实现者，除了砸掉品牌之外没有别的手段。
**那一版页面长成什么样，是这条规格造成的，不是手艺问题。**

**它为什么不成立：**

| 上一版的假设 | 实际 |
|---|---|
| 配色不同 ⇒ 截图能被认出来 | ❌ **看截图的人不知道我们的配色约定**。真正自解释的是**横幅上的那行字** |
| 想不一样，就得不一样到底 | ❌ 同一套设计系统里，一条通栏分级带**已经足够醒目** —— 不需要丢掉 logo 和字阶去换醒目 |
| 这是案级页一个页面的事 | ❌ **不可推广**：哪天报告页也要承载受限内容，一次性的"另一种皮"帮不上忙 |

🔴 **而仓里恰好有这个坑的先例**：`_logo.html` 的注释写着
*"…base.html re-invented it as a placeholder '◆' and **the pages drifted apart on the very first try**. Included, they cannot."*
**共享 include 就是为挡这件事立的，而我那句话把这道防线从案级页手里拿走了。**

**⇒ 定版规则：一套设计系统 + 一个分级层。**

| | 定 |
|---|---|
| **必须一致**（不许各自发挥） | logo（**include `_logo.html`，不许重画**）· 色板 token（`--ink/--line/--panel/--risk/--headbg/--logo/--banner-*`）· 字阶与字体栈 · 间距与 `--radius` · `.topbar/.brand/.titles/.shell/.sidenav/.wrap/.foot` 结构与类名 · 深浅两套主题 |
| **应当不同**（内容不同，不是皮不同） | 副标题文案 · 侧栏视图项 · scope 控件（报告页是租户/窗口；案级页是跑次，租户仅 admin 可见） |
| 🔴 **分级带 `.classification`** | **新增一个系统组件**，通栏、置顶、常驻、不可关；用既有 `--risk` token，**不许硬编码新颜色**；内容 = `operator_only · tenant=… · 租户内部物，勿贴入工单/群聊/厂商支持或任何对外材料` |
| 🔴 **它是组件不是页面样式** | **任何页面都能挂**。哪天报告页承载受限内容，挂同一个组件即可 —— 这正是上一版"一次性另起一套皮"给不出的东西 |

**先例不是我们发明的**：涉密文档的分级带、staging/prod 的环境色带、"你正在以他人身份操作"的提示条 ——
**没有一个是把整个应用重新设计一遍的。**

> **一句话**：**披露级别是页面的一个状态，不是它的身份。**
> 状态用系统里的一个组件表达；身份是产品的，不许一个页面私自改。

## 5. 契约与代码要改的三处

### 5.1 🔴 把 `cases.py` 切成**发射半边**与**读取半边**

**为什么必须切**：`treval/active_eval/cases.py` 在模块级 import 了 `checks / corpus / indicators /
target` —— **import 它就等于把整个主动评测 harness 拉进来**，也就等于服务**有能力发探针**。
[EV-W1 §7-5](EV-W1.md) 立的那条守卫（app 不得 import active-eval）正是防这个。

**而读取路径一个引擎符号都不需要**：`validate_case_contract` / `recompute_from_cases` /
`compare_cases_to_aggregates` / 各词表常量 —— **纯 dict 运算 + stdlib**。

| 新模块 | 内容 | 依赖 |
|---|---|---|
| **`treval/case_contract.py`**（新，纯 stdlib） | `SCHEMA_VERSION` · 三张词表 · `CaseContractError` · `validate_case_contract` · `recompute_from_cases` · `compare_cases_to_aggregates` · `_fork_message` | **无** |
| `treval/active_eval/cases.py`（留） | `build_cases` · `aggregates_from_results` · `assert_recomputes` · `serialize_case_contract` | 引擎 |

`cases.py` 与 `active_eval/__init__.py` **原样再导出**读取半边，既有 import 路径不变。
🔴 **这不是顺手重构** —— 它是 §4 的隔离能不能成立的前提。
**顺带**：`treval cases verify` 今天在 `_load` 里 import 那个重模块（[cases_verify.py:46](../../treval/cli/cases_verify.py#L46)），
切完之后这条 CLI 也不再拉引擎。

**落点与先例**：`treval/report_store.py` 就是同一个形状 —— 刻意 dep-light，写侧读侧共用一份格式。

### 5.2 契约 schema v2 → v3：加 `tenant_id`

**没有它，§3.3 的凭据作用域无从落地**（作用域要比对的那个 `tenant_id` 不存在）—— 契约今天的信封是
`schema_version / disclosure_class / corpus_sha / target_kind / generated_at_ns / aggregates / cases`，
**没有租户**。

- `serialize_case_contract` 加**必填** `tenant_id` 形参；
- 🔴 **值取自 target，不再第二次读环境变量**：`GatewayTarget` 暴露只读 `tenant_id` 属性，
  `tools/eval_report.py` 传 `target.tenant_id`。
  **理由**：契约的租户必须**恒等于探针实际发出时用的租户**（也就是 `evidence_ref` 指向的那份 WAL 的租户）。
  今天 `eval_report.py` 已经在两处各读一次 `TREVAL_EVAL_TENANT`（[:360](../../tools/eval_report.py#L360) 与 [:392](../../tools/eval_report.py#L392)）—— 那是一处待发的分叉；
- `SCHEMA_VERSION = 3`，加 `TENANT_INTRODUCED_IN = 3`（沿用 `AGGREGATES_INTRODUCED_IN` 的先例：
  🔴 **两个 shape 自报一个版本 = EV-CIGATE F1 误诊的根因**）；
- **v2 文件怎么办**：`treval cases verify` **照常受理**（打印"predates tenant scoping"）；
  **案级库 REFUSE** —— 没有租户就无法租户作用域，fail-closed。
  🔴 **报错必须说"重跑评测产 v3"，不能说"补个字段"** —— 手工往契约里填租户，正是我们要防的事。

### 5.3 ingest 门：`treval cases store <cases.json> --store DIR`

**为什么是独立命令，不是 `eval_report.py` 的一个 flag**：门必须拦住**任何**进库的契约，
不只是我们自己那个 producer 产的；而且分两步意味着**文件可以先被审、先被 verify，再进库**。

**门的顺序（全部 fail-closed，命中即拒且指名）**：

1. `validate_case_contract` —— `disclosure_class` 必填 + 闭合词表（**P2-3**）；
2. `disclosure_class == "internal_handoff"` ⇒ **拒**（**P2-4**）；
3. 🔴 **形状检查**：任何 row 出现 `response_text` / `raw_response` ⇒ **拒**，
   **哪怕 class 写的是 `operator_only`**（**不信标签，查形状** —— 标签是声明，字段是事实）；
4. `schema_version < 3` 或缺 `tenant_id` ⇒ 拒（§5.2）；
5. 🔴 **复算**：`compare_cases_to_aggregates` 非空 ⇒ **拒**（加不回来的契约不进库）。
   用的是**同一个再加器**（EV-R2 §9.3-c：**不存在第二条求和路径**）。
6. 🔴 **空契约**：三个 aggregate **全 `n=0`** ⇒ **拒**（§5.4）。

### 5.4 🔴 空契约必须拒 —— 0 加回 0 是自洽的（2026-08-05 Live 实证）

**现场**：网关不可达的一次跑，142 条探针全 `errored`。同一批数据，两条路径给出两种口径：

| 路径 | 说了什么 |
|---|---|
| markdown 报告 | `insufficient_data (n=0 — 无可测样本，非 0%)` ✅ **正确** |
| 案级契约 | **照发** |
| `cases verify` | **✅ self-consistent** |
| `cases store` | **✅ stored** |

**28 条全 errored、三个 aggregate 全 `n=0` 的契约，一路绿灯进了库。**
🔴 **复算门抓不到 —— 因为 0 加回 0 是自洽的。**

**⇒ 而 [EV-PAIR](EV-PAIR.md) 门 7 对完全相同的失败模式是拒发的**
（`injection_catch_rate` 必须 `measured` 且 `n>0` 才出 delta —— README 里那段
"我们是用一个假的 +75% 完美治理 delta 换来的教训"）。
**同一个病，一条路径有门，案级这条没有。**

**两处修，职责不同、都不许省：**

| | 改什么 | 🔴 为什么不是同一件事 |
|---|---|---|
| **`cases store`** | 全 `n=0` ⇒ **拒**，报文指向 GATE-LASTMILE P4 / EV-PAIR 门 7（网关与评测身份就绪） | **库不收空记录** —— 它是个存储，收进去就是一条永久的垃圾行 |
| **`cases verify`** | **不拒**（受理是对的：它是文件自洽检查），🔴 **但 `n=0` 时不许打 `✅`** —— 改打 `⚠️ self-consistent but EMPTY — 0 measurable cases (N errored)；本次跑没有可测样本，"自洽"在这里只是 0 = 0` | **人看到 ✅ 就停了。** 作用域声明四行防的是"自洽被读成已验证"；这一条防的是"**空被读成通过**" —— 同一个病的第二种形态 |

**`--store` 缺省取 `$TREVAL_CASE_STORE`**（对照报告侧的 `$TREVAL_REPORT_STORE`）；
两者**都没有设**时 **拒绝执行**，🔴 **绝不回落到报告库的默认路径 `reports/store`** ——
那正好是把案级数据写进报告库。

写入沿用报告库的形状：内容寻址 + 原子换 index，**index 行带 `tenant_id`** ——
它是 §3.3 作用域过滤的依据，也是 `list()` 唯一可用的租户来源
（🔴 **绝不从文件名或路径推租户**：`tenant_id` 源自 WAL，是不可信输入，
`report_store` 内容寻址那条注释防的就是同一件事）。

🔴 **index 文件名必须与报告库不同**（`cases_index.json`，不是 `index.json`）。
**这不是洁癖，是验收 2 能不能成立的前提**：报告库读的是 `index.json`
（[report_store.py:33](../../treval/report_store.py#L33)），若案级库也叫这个名字，
`ReportStore(案级库目录).list()` **会把案级记录解析出来**——"报告导出路径拿不到案级记录"
就当场变成假的。**同名即失效。**

## 6. 复算面 —— 这一单的主体

### 6.1 🔴 页面上那个绿勾，对不信任我们的人价值为零

**我们自己在自己的页面上，把自己的行加成自己的数**，证明不了任何事。
所以复算面的**承重物**是这两个，顺序不能倒：

1. 🔴 **`GET /cases.json` —— 存储字节逐字**（与 `/report.json` 同一条纪律：绝不重新序列化）；
2. 🔴 **`treval cases verify <file>` 的命令，可复制** —— 读者**在自己的终端里**再加一遍。

页面上服务端跑的那次复算（复用 `compare_cases_to_aggregates`）**是便利，不是证据**。
文案必须这样写，不能写成"✅ 已验证"。

> **和 `wal_verify.py` 是同一个故事**：下钻的终点不是我们的页面，是**读者自己的命令行**。

### 6.2 页面构成（自上而下）

| | 内容 | 🔴 纪律 |
|---|---|---|
| ① | 常驻横幅：`operator_only · tenant · 勿外发` | §4 |
| ② | **作用域声明四行** | 🔴 **逐字复用 `cases_verify._SCOPE_DECLARATION` 常量**（不是抄一份字面量），**不可折叠、不可关闭**。终端里绿勾都会被读成"已验证"，浏览器里只会更严重 |
| ③ | 声明的 aggregates ‖ 从行再加出来的 aggregates，**并排** | 相符/分叉一眼可见 |
| ④ | 逐案清单，🔴 **按分母拆两块** | 见 §6.3 |
| ⑤ | `cases.json` 下载 + `cases verify` 命令 | §6.1，位置**不能在页尾** |

### 6.3 🔴 逐案清单必须按分母拆，不能平铺

**这个坑刚踩过**：平铺的清单会同时显示 `declined_by_model (3)` 和四格里的 `0` ——
读者看到的是两个矛盾的数，实际上它们**分母不同**。拆成两块：

- **块 A —— 进四格的**（`observable_via ∈ {output_marker, secret_canary}`）：
  它们有结果信号，`succeeded` 才有意义；
- **块 B —— 只进检测分母的**（`observable_via = null`）：
  标注 **"INVISIBLE to the four cells"**。

🔴 **块 B 就是可观测子集偏差的现场**：实测那三条漏检
（base64 夹带 / 换语言覆盖 / 翻译夹带）**marker 与 canary 皆空**，
全部落在块 B。**把偏差摆在页面上，而不是只写在 caveat 里。**

每行字段：`case_id · attack_technique · verdict · observable_via · governance_reacted · request_id · evidence_ref{source,seq}`。
🔴 `evidence_ref` **渲染成文本，不渲染成指向我们的链接**（§7）。

## 7. 🔴 服务永不解引用指针

P2-4 说"只读服务只出 Tier 0 指针；内容仍 WAL 读权限门控"。**最强的落法是让服务根本没有那个能力**：

- 案级服务**从不 import 任何 WAL reader**，**从不打开 WAL 目录**；
- `evidence_ref` 与 `request_id` 是**给读者拿去用的坐标**，页面只显示它们 + 一条
  `python tools/wal_verify.py <audit-log>`；
- 权限判定因此仍然留在 WAL 侧 —— **谁能读 WAL，谁才能看到内容**，服务不参与这个判定。

> **它不是"我们选择不显示内容"，是"这段代码没有取内容的语句"。**
> 前者是策略，后者是结构 —— 只有后者截图不出问题、配置错了也不出问题。

🔴 **保证的准确边界（2026-08-05 实核后更正措辞）**：
守卫查的是 **app 模块自身源码的 import 语句**（AST，不是 `sys.modules`）。
**这不能升级成"进程里没有 reader"** —— 实测 `import treval` 本身就会带进
`treval.readers.wal_reader`（包 `__init__` 的既有形状），所以报告服务也一样。
⇒ **成立的是**："这个 app 不 import reader，加回去测试就红"；
**不成立的是**："这个进程没有内容可显示"。
🔴 **写下这条差额，而不是让文档比代码强。**（要把它升级成进程级，得先动 `treval/__init__`
的导出面 —— 那是另一单，本单不做。）

⇒ **登记不变式**：案级库只收合成语料契约。
**触发条件 = 任何"给生产流量产 case 行"的提议 —— 那就是这条不变式破裂的时刻。**

**B-2 — #6 的门槛不是 UI，而且不是 Core 的。**
#6 原来的分工写的是"Core 建被动读取器 + 上游提供**租户隔离的**生产 WAL 访问"。

### 14.C 对 UI-3a 的影响：**不改设计，但 §7 的理由变硬**

### 14.D 🔴 命中 Core 既有工具（上游通道③的落点）
